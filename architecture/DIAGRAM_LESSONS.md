# Diagram design — standards, pitfalls, and how to handle them

Read this before changing any diagram in the tree. It records what each diagram
set is, the standards a change must keep, the failures already paid for, and the
method that settled each one. ROADMAP O188 and O189 carry the evidence.

## 1. The three sets, and which file is the source

| Set | Source | Derived from it | Gate |
|---|---|---|---|
| `architecture/diagrams/*.svg` (11) | the SVG files themselves | the inlined copies in `architecture/index.html` and `architecture/pdf/`, both regenerated by `build.sh` | `sh build.sh --check`: the table's pins (`textfit/pins.py`), text fit through `textfit/textfit.py`, inlining, and PDF coverage (not PDF bytes, O191) |
| `architecture/platform-views/*.html` (22) | each HTML file, hand-authored; no build step | nothing | `platform-views/check.py`, whose text-fit arm is the same `textfit.py` |
| `docs/diagrams/*.svg` (14) | the fenced `mermaid` blocks in the docs | `src/*.mmd`, then the SVGs rendered by the digest-pinned `minlag/mermaid-cli:10.9.1` with `mermaid-config.json` (recipe in `docs/diagrams/README.md`) | none for fit (ruled, O189); no drift gate yet (O190) |

`arch-check` runs the first two. The `fonts are openly licensed` preflight in
`tests/battery.sh` covers every set, the served consoles, the site and the brand
assets. Never hand-edit a derived file: edit the source, regenerate, and check
that the derived files match.

## 2. Fonts: only openly licensed faces are named (the maintainer, 2026-09-15)

No proprietary font is named anywhere in the tree, and no font file is shipped
for it:

| Role | Stack |
|---|---|
| sans | `"DejaVu Sans", "Noto Sans", sans-serif` |
| mono | `"DejaVu Sans Mono", monospace` |
| serif | `"DejaVu Serif", "Noto Serif", serif` |
| the book, including its live Mermaid | `"IBM Plex Sans"` / `"IBM Plex Mono"` / `"GFS Didot"`, which the site vendors |

Vendor keywords that request an OS UI font (`-apple-system`, `ui-monospace`,
`system-ui`) are proprietary by proxy and are not used.

A reader without these fonts sees their own system's generic family. The decision
removes the tree's dependency on proprietary fonts, not the fonts a reader has
installed, and the fit standard below is a worst case over the named faces for
exactly that reason.

## 3. Standards

**`platform-views`**
- `viewBox="0 0 1200 800"` or taller. No external request of any kind (O78).
- Shapes: a node is an `rx="6"` rect, a zone `rx="8"` painted before arrows, and a
  label mask a small `rx="2"` rect filled `#04080a`. At most 9 nodes and 2 accent
  (teal) nodes per diagram.
- Geometry: no diagonal connector, no connector behind a box that is not its
  endpoint, no label mask painted over by a later node.
- Type: titles 12 semibold sans; detail lines 9, 8 or 7 mono; labels 7–8 mono with
  letter-spacing. Never below 7.

**`architecture/diagrams`**
- Text is styled by class: `.h` 17px/600, `.l` 13.5px/600 (14px in
  `retrieval-stack`), `.b` 12px, `.s` 11px, `.mono` 11px.
- A per-element size override is a last resort.

**Every set**
- **Text fit (O188, O189):** every `<text>` ends at least 4 units inside the
  smallest rect holding its anchor, else inside the viewBox. Past the viewBox is
  reported as a CLIP.
- **Accessibility:** `role="img"`, `aria-labelledby`, and a `<title>` before
  `<defs>`. The `<desc>` says what the picture says, and changes whenever the
  picture does.
- **Encoding:** LF line endings only.

## 4. Width is what goes wrong, and how it is decided

**One font environment is not "fits".** Measured on the same 611 lines: the
Windows pane (Segoe UI) found 4 spills, headless Chromium with DejaVu Sans found
22, and the committed PDFs, set in Noto Sans, carried the 4 with two clipped
mid-word. Measured faces rank Segoe < Trebuchet < Arial/Liberation < Verdana ≈
DejaVu. A standard set by the narrowest face is O188's Consolas trap again.

**The standard is a table, not an estimate.** `architecture/textfit/advances.tsv`
holds, per codepoint, the per-glyph maximum advance over the named faces:
- DejaVu Sans and Noto Sans, Book and Bold;
- DejaVu Sans Mono;
- DejaVu Serif and Noto Serif, upright and italic;
- the Noto script faces and the fallbacks a renderer really uses (Noto Looped
  Thai, Noto Sans Math);
- Arabic priced by the positional form its joining context forces, and a ligature
  at its widest reading.

**A cell is priced only where every modelled reader draws it** (O189, panel 2).
`textfit/readers.py` is the one reader model, shared by the generator and the
calibration. Per slot it has a DejaVu-primary and a Noto-primary stack, each also
with Noto Looped Thai in place of Noto Sans Thai, followed by Noto Sans Arabic,
Thai, Devanagari and Math, in every style a column renders.
- A reader draws a codepoint with the first face of its stack that maps it, and
  that face's advance joins the maximum.
- Where some reader has no such face, the cell is `-` and textfit fails closed.
  Hebrew, Armenian and the math symbols one Noto Sans Math release lacks are
  therefore refused, not priced from a face that reader never has.
- The model is declared, not observed (O195).

**CJK is priced by rule, at 1.05 em per character.** That is one em plus the
largest positive default-on adjustment in the declared Noto Sans CJK SC faces,
+50/1000 em of kern. A positive pair adjustment grows with the glyph count while
the 4-unit budget does not, so kerning cannot be left to the budget. An unassigned
codepoint in the CJK blocks is refused.

**A font is pinned by digest, and the maximum is over two releases** (O189). A
version string is not an identity: Debian's and Alpine's DejaVu 2.37 are
different files. `textfit/fonts.tsv` lists every file by slot and sha256 — slot
`debian`, the bookworm packages, and slot `noto-23.7.1`, the notofonts monthly
release fetched per file — and it is the one list the generator and the
calibration share. `gen_advances.sh` regenerates the table by hand,
byte-identically, and refuses a file whose digest disagrees. `textfit/pins.py`,
which `build.sh` runs in both modes, fails when the table's header and the pins
disagree. A newer Noto release is not covered (O193): 2025.05.01 widens Arabic
heh and digits, the minus sign and the math arrows, and the generator cannot
model it yet.

**What the table refuses rather than prices.** Each of these fails closed, like
anything else textfit cannot price:
- a `-` cell, which some modelled reader draws with no face (above);
- an unassigned codepoint in the CJK blocks;
- a line a shaper can recompose, meaning a base followed by a mark the face has
  precomposed, outside Arabic (O194).

`textfit.py` also refuses to run on a Python whose Unicode version is not the
table's.

Two flat estimates failed: 0.56 em flagged 83 lines and missed 3 real spills, and
0.60 em was called a monospace bound while DejaVu Sans Mono advances 0.60205.

**The 4-unit padding is the table's error budget.** A sum of advances has no
kerning and no shaping. Calibration must show, per slot, renderer − table < 4 on
every line, zero misses, and false flags at most 7% of flagged lines, each named.
Kerning is priced for CJK only. In the table's own faces, two to four maximal
pairs at 17 px could exceed the budget (O196). Today's text does not contain such
a run, and nothing in the gate would notice one that did.

**How to measure:**
- **Quick, against the standard,** in a container, never with a host Python (its
  Unicode version differs, and textfit refuses it): from the repo root,
  `MSYS_NO_PATHCONV=1 docker run --rm -v "$PWD/architecture:/a:ro" -w /a python:3.12-slim python3 textfit/textfit.py diagrams/<file>.svg`.
  Add `--widths` for per-line JSON: `over` > 0 fails, negative is inside the padded
  edge.
- **In a renderer, which is calibration:** use the tracked, hand-run harness in
  `architecture/textfit/calibrate/`; its README has the recipe. It renders in
  headless Chromium inside `minlag/mermaid-cli@sha256:f0e8d29e…` with every face
  EMBEDDED from the files `fonts.tsv` pins, one slot per page, and each face named
  explicitly in the stack. It reads `getComputedTextLength()`, which device scale
  does not move. It fails on:
  - a platform font, and a header face no fixture string used;
  - a row it cannot join by file and document index;
  - a character no reported face maps, which is a box;
  - a CJK face drawing a character outside the CJK blocks;
  - faces the reader model did not predict.

  The CJK kerning bound is read from the faces' own tables by its
  `cjk-font-data` step.
- **The Browser pane refuses some local files** (standalone `.svg`, the scratchpad,
  `.battery/`, some platform-views pages). Measure the architecture SVGs inlined in
  `index.html`, with its paged sections unhidden first.
- **Mermaid labels are HTML in `<foreignObject>`,** sized at render time by the
  render image's fonts. A check inside that image agrees with itself by
  construction and cannot see a viewer's font.

## 5. Fixing a spill — in this order

1. **Reword or shorten**, keeping every fact the line states. Abbreviate in the
   diagram's own style (`·`-separated fragments, suffix forms like `_EMBED_URL`).
   Check a term against the code before shortening it: "no creds" overclaimed where
   only the URL's userinfo is stripped.
2. **Re-wrap** words between the lines of the same sentence where the lines exist.
3. **Only if shortening would drop a fact**, cut that line by 1 pt, never below 7,
   keeping sibling lines readable together.
4. **Drop letter-spacing** on a small label before truncating its word.
5. **Split a long free-standing sentence** into two `<text>` lines, only where the
   vertical space collides with nothing.
6. **Move a label or grow a card** only when no wording fits, and keep every sibling
   inside.

Keep a load-bearing word at a smaller size rather than weaken it. A rewording can
also expose a false claim: `Mann/Männer` was listed as an irregular pair, and the
code reaches it by a suffix rule. Fix the fact, and say so.

**Figures inside diagrams are gated** by the `prose figures` preflight. Keep every
number, and the words beside it, recognisable.

## 6. Process traps already paid for

**Gates and calibration**
- **A gate can be green over a defect it cannot see.** The geometry arms read rects
  and never a text's width, so 113 lines spilled under a green `check.py`.
- **A check calibrated on one machine measures that machine.** Calibrate against
  the widest face a reader can get, and against a layout confirmed by eye in that
  face.
- **Isolated Arabic letters are not a bound.** Positional forms are wider in 447 of
  3,330 two-letter words.
- **A renderer falls back to faces your table does not know**: Noto Looped Thai
  made the worst line. Record the platform fonts every measurement used.
- **An image digest pins the image, not what you install into it.** The
  calibration image carries no Noto; the first calibration's Noto came from an
  unversioned `apk add`, and a CDP row reports a family and a PostScript name,
  never a version. Pin every font file by sha256 and embed it.
- **Installed fonts let fontconfig choose.** With the standard's own files
  installed, Thai rendered in FreeSerif and Devanagari in FreeSans, and no Noto
  script face was used at all.
- **Judge against the table you are testing.** A fixture priced by the two-slot
  maximum hid a ligature the Debian slot really formed; priced by the Debian table
  the same renders were over by 0.73 px.
- **The browser credits a box to the face that drew it.** On the 23.7.1 page
  U+2AAC and U+2BFE rendered at 6.609 px, glyph 0's 0.600 em, while CDP named the
  page's primary face. Only a check against that face's cmap sees the box.
- **A fallback face nobody lists draws the gaps.** Math symbols no stack face maps
  fell to the render image's own DejaVu Sans, FreeMono, an emoji face or the CJK
  face, and a CJK face drawing one was counted as CJK. Price a cell only where
  every reader has a face for it.
- **A substring width is not an advance.** `getSubStringLength` includes kerning
  and snaps to 1/64 px. Measure a CJK advance with `font-kerning:none`, and take
  the kerning bound from the font's tables.
- **An untracked directory is invisible to the preflights.** They read tracked
  files; `architecture/textfit/` failed `fonts are openly licensed` the moment it
  was intent-to-added.
- **Prove a new arm fires before believing it.** Every text-fit arm carries a
  premise fixture, run red on the unfixed tree first.

**Edits**
- **Apply scripted edits all or nothing:** every anchor matches exactly once, bytes
  in and bytes out with LF kept, and the result equals the helper's own copy byte
  for byte. Then read the diff.
- **Helper agents proposing edits stay read-only.** Each gets its own scratch folder
  and returns exact replacements in a file.

**Derived artifacts**
- **A derived raster follows its source.** When a brand SVG's fonts change,
  re-render its PNG. Uploading GitHub's social preview is a separate, manual step.
- **An engine change moves relational prose no gate reads** (O105). Read every
  diagram that names the changed thing, in all three sets, `<desc>` included.

## 7. Checklist for any diagram change

1. Edit the source file for its set, never a derived copy, and name only the fonts
   in §2.
2. Run `textfit.py` on the file in `python:3.12-slim` (§4), then
   `docker compose run --rm arch-check`, green. For `architecture/diagrams`, run
   `build.sh` first so the inlined copies and PDFs follow.
3. Look at the rendered page, and measure any line near a box edge in a renderer.
4. Update the `<desc>` in the same edit.
5. Run the preflights (`prose figures`, `fonts are openly licensed`).
