# Diagram design — standards, pitfalls, and how to handle them

Read this before changing any diagram in the tree. It records what each diagram
set is, the standards a change must keep, the failures already paid for, and the
method that settled each one. ROADMAP O188 and O189 carry the evidence.

## 1. The three sets, and which file is the source

| Set | Source | Derived from it | Gate |
|---|---|---|---|
| `architecture/diagrams/*.svg` (11) | the SVG files themselves | the inlined copies in `architecture/index.html` and `architecture/pdf/`, both regenerated by `build.sh` | `sh build.sh --check` (inlining and PDF coverage, not PDF bytes) |
| `architecture/platform-views/*.html` (22) | each HTML file, hand-authored; no build step | nothing | `platform-views/check.py`, run with the above by the `arch-check` service |
| `docs/diagrams/*.svg` (14) | the fenced `mermaid` blocks in the docs | `src/*.mmd`, then the SVGs rendered by the pinned `minlag/mermaid-cli:10.9.1` (recipe in `docs/diagrams/README.md`) | none |

Never hand-edit a derived file. Edit the source, regenerate, and check that the
derived files match.

## 2. Standards for `platform-views`

- **Canvas.** `viewBox="0 0 1200 800"` or taller. System font stacks only: sans
  for titles, `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` for
  detail lines, Georgia for the italic callout. No external request of any kind
  (O78).
- **Shapes.** A node is an `rx="6"` rect; a zone is `rx="8"` and is painted before
  arrows; a label mask is a small `rx="2"` rect filled `#04080a`. At most 9 nodes
  and at most 2 accent (teal) nodes per diagram.
- **Geometry.** No diagonal connector. No connector passing behind a box that is
  not its endpoint. No label mask painted over by a later node.
- **Text fit (O188).** Every `<text>` fits inside the smallest rect that holds it,
  with 4 units of padding on each side. Text that no rect holds fits inside the
  viewBox, 4 units from its edges.
- **Type scale.** Titles 12 semibold sans. Detail lines 9, 8 or 7 monospace.
  Labels 7–8 monospace with letter-spacing. **Never below 7.**
- **Accessibility.** `role="img"`, `aria-labelledby`, and a `<title>` before
  `<defs>`, with slug-prefixed ids. The `<desc>` is the diagram for a
  screen-reader user: it must say what the picture says, and it changes whenever
  the picture does.
- **Encoding.** LF line endings only.

## 3. Width is what goes wrong, and how to measure it

**Glyph advance differs by platform, and a layout drawn on one machine spills on
another.** Measured: the Windows browser pane renders Consolas at **0.55 em** per
monospace glyph, while Menlo, SF Mono and DejaVu Sans Mono are about **0.60 em**. A
line drawn to fit on Windows can overflow by 9% on a Mac. Letter-spacing adds its
em value times the font size **per character**: a 6-letter `SQLITE` label at
7 px with `0.08em` did not fit a 36-wide mask until the spacing was dropped.

**How to estimate width** — the formula `check.py` uses:
`characters × font-size × em + letter-spacing × font-size × characters`, with em
0.60 for monospace. **That is a bound.** For proportional faces the gate uses
0.56, which is an average and **not** a bound: prose width depends on the letters.
On `architecture/diagrams`, a 0.56 estimate flagged 92 lines where the renderer
found 4. Settle proportional prose with a renderer, never with the estimate.

**How to measure in a renderer** (Browser pane, `javascript_tool`): for each
`<text>`, take `getBBox()` and compare it with the smallest rect containing its
centre. Lessons from doing it:

- **Label a result with `document.title`.** A local file opens as a `data:`
  snapshot, so `location.pathname` is the whole encoded document; it once
  returned 64 KB.
- **The pane refuses some paths.** It refused standalone `.svg` files, anything in
  the scratchpad, anything under `.battery/`, and in-tree platform-views pages (06, and
  later 22) while opening their neighbours. So some diagrams can only be
  verified by the gate in a given session; say which, and do not claim a look. For the 11 architecture
  SVGs, measure them inlined in `architecture/index.html`. Unhide its paged
  sections first, since a hidden element has no box.
- **Mermaid labels are HTML in `<foreignObject>`.** The label width was frozen by
  mermaid-cli's fonts at render time. Compare each label's `scrollWidth` with its
  `foreignObject` width; `getBBox` on `<text>` finds nothing there.

## 4. Fixing a spill — in this order

1. **Reword or shorten**, keeping every fact the line states. Abbreviate in the
   diagram's own style (`·`-separated fragments, suffix forms like
   `_EMBED_URL`). Check a term against the code before shortening it: "no creds"
   overclaimed where only the URL's userinfo is stripped.
2. **Only if shortening would drop a fact**, cut that line by 1 pt, never below 7,
   and keep sibling lines in the same box readable together.
3. **Drop letter-spacing** on a small label before truncating its word.
4. **Split a long free-standing sentence** (a callout) into two `<text>` lines,
   and only where the vertical space collides with nothing.
5. **Move a label** only when no wording fits. The refine column's `2 · RECORD`
   sat past its lane at x=1112, and no text change could fix that.

Keep a load-bearing word at a smaller size rather than weaken it. `PRESERVED`
names the rotation doctrine and `discard` matches `discard_pending_file`.

**Figures inside diagrams are gated.** The `prose figures` preflight in
`tests/battery.sh` reads counts from 20, 21 and other platform-views pages.
Keep every number, and the words beside it, recognisable, and run the preflight
after a rewording.

## 5. Process traps already paid for

- **A gate can be green over a defect it cannot see.** The geometry arms read rects
  and lines and never a text's width, so 113 lines spilled while `check.py`
  passed, and the maintainer saw it on the page. Ask what a check can *see*.
- **Calibrate a new check against a layout confirmed by eye.** The first text-fit
  arm bounded free text by the lanes (80 in from each edge) and flagged the set's
  standard `LEGEND` labels. The right bound was the viewBox.
- **Prove a new arm fires before believing it.** The text-fit arm has a premise
  fixture, and it ran red on the unfixed tree (113 problems) before any fix
  landed.
- **Measure only the line you added, and you miss the ones beside it.** One edit
  checked its own note and never read the existing box text.
- **An engine change moves relational prose no gate reads** (O105). After
  changing the engine, read every diagram that names the changed thing, in all
  three sets, `<desc>` included. Diagram 18's `<desc>` still called the served
  embedder's repair egress a gap after that gap had closed.
- **Apply scripted edits all or nothing.** Every anchor must match exactly once or
  nothing is written; files stay bytes-in, bytes-out with LF kept; then read the
  diff.
- **Helper agents proposing edits must stay read-only**, returning exact
  replacements in a file, not HTML-escaped text in a message. Give each its own
  scratch folder: one overwrote a shared helper script mid-run.

## 6. Checklist for any diagram change

1. Edit the source file for its set, never a derived copy.
2. `docker compose run --rm arch-check`, green. For `architecture/diagrams`, run
   `build.sh` first so the inlined copies and PDFs follow.
3. Look at the rendered page in the Browser pane, and measure any line near a box
   edge.
4. Update the `<desc>` in the same edit.
5. Run the `prose figures` preflight if the diagram carries a count.
