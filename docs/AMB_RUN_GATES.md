# AMB run gates — the acceptance checklist

**What this is.** The gate set for a run of the procedure in
[AMB_REPLICATION.md](AMB_REPLICATION.md): what must pass before a number from
that run is believable, and what must be published beside it for the number to
mean anything.

**How it was produced.** Derived independently from four sources — AMB's own
harness, this project's measurement doctrine, control-arm design, and
anti-inflation analysis of the choices this run makes — then red-teamed from
three adversarial angles (fake a high score, fake a low score, make an honest
mistake) and synthesised into one ordered list. Constants were measured from
the cached splits during that pass, not inherited from any document.

**Levels.** BLOCKING = the number is invalid if it fails. IMPORTANT = the number
is meaningless unless this is published beside it. INFO = record it.

**The residual-risk section at the end is load-bearing.** It lists what no gate
here catches. A gate list that claims to catch everything is the failure it is
meant to prevent.

---

Verified against the AMB clone and the undercroft tree during this pass (marked ✓ where I measured the constant myself rather than inheriting it): locomo10 = 272 docs / 1540 queries / 10 users / 9 empty `gold_ids` / 6 non-string golds / `meta.category` {open-domain 841, temporal 321, single-hop 282, multi-hop 96} with top-level `category` None on 1540/1540; personamem/32k = 195 docs / 589 queries / 37 users / 0 timestamps / 0 query_timestamps / `retrieval_query` on 589/589; AMB `chunk_text` yields **876** locomo chunks (per-wing conv-44:116, 42:107, 43:98, 41:95, 50:92, 48:91, 47:90, 49:72, 26:64, 30:51) and **2042** personamem chunks (37 wings, 40–64); `''.join(chunks) == content` and 0 U+FFFD on both; gold_ids ⊆ document ids with union 272/272; injected `query_timestamp` is early by 96–203 days on 10/10 conversations, 182/272 documents are dated after it, 1075/1540 queries have a gold document after it; longest-option heuristic on personamem = 51.6% overall (suggest_new_ideas 0.0%, generalizing_to_new_scenarios 100.0%).

# THE GATE CHECKLIST

Levels: **BLOCKING** = number is invalid if it fails. **IMPORTANT** = number is meaningless unless this is published beside it. **INFO** = record it.

## Stage A — pre-flight (before anything is built or ingested)

**A1 · BLOCKING · Configuration frozen and hashed before the first query.**
Emit one manifest: git rev + `git status --porcelain`, engine image digest, engine version, vault security level, the **complete** `UNDERCROFT_*` environment as passed to the container, k, chunker constants read from `$AMB/src/memory_bench/utils.py` (not hardcoded), tokenizer, wing/room mapping rule, dataset sha256s, `ranked_at`, `as_of` policy, answerer + judge model ids, batch size, AMB prompt/judge template hashes obtained by importing the clone's `build_rag_prompt`/`build_judge_prompt`, scaffold hashes, and the pre-registered headline number (dataset, arm, regime, timestamp variant). Hash the block; timestamp the freeze. Re-hash at arm end. **Pass:** freeze timestamp precedes the first retrieval; start-hash == end-hash; the published headline is the pre-registered one. Any mid-arm change voids the arm. **Catches:** garden-of-forking-paths tuning (AMB saves partial results after every unit, so peeking is the default), and post-hoc headline selection across the 20+ reportable figures this design generates.

**A2 · BLOCKING · Answering and judging subagents spawn with an empty tool allowlist.**
No Read/Glob/Grep/Bash, no WebSearch/WebFetch, no MCP, no filesystem root. Record the spawn config hash. **Pass:** literally empty for both roles. **Catches:** the gold answers sit at `$AMB/data/locomo/locomo10/queries.json.gz` on the same filesystem, and LoCoMo is public on the web. One Read tool produces a near-perfect fake score that every content-parity gate passes cleanly. This is the single largest hole in an otherwise thorough gate set.

**A3 · BLOCKING · Binary and image freshness proven, not assumed.**
Build with `--build`; probe the **running container's** binary for a symbol only HEAD carries (`--help | grep -c <HEAD-only flag>` ≥ 1) and record `--version` == workspace `Cargo.toml` version and the image digest. Every docker invocation carrying container paths is prefixed `MSYS_NO_PATHCONV=1`; the driver sets `pipefail`. **Catches:** the documented stale-artifact family (target volume serving an old rlib, `docker compose build` serving a stale `/src`, MSYS turning `-e CARGO_TARGET_DIR=/build` into a Windows path behind a pipeline that exits 0). A stale binary passes every old check by construction.

**A4 · BLOCKING · Corpus provenance is the cached export, byte-identified.**
sha256 all four files (`{documents,queries}.json.gz` for both splits) into the manifest; read every count from the files. **Pass:** the ✓ counts above reproduce exactly, and top-level `category` is None on 1540/1540 (proof the cache shape is what you think it is). One declared source for **both** documents and queries — never live-adapter documents with cached queries. **Catches:** re-deriving from raw `locomo10.json` and forgetting `_SKIP_CATEGORIES={5}` (1986 QA pairs instead of 1540, a silently incomparable denominator); and mixing sources, which would hand personamem a `timestamp` its own export does not have (0/195) and thereby hand undercroft's entire temporal machinery a corpus AMB never had.

**A5 · BLOCKING · Semantic floor and admission gate are DECLARED, not calibrated live.**
Set `UNDERCROFT_SEMANTIC_FLOOR` and `UNDERCROFT_SEMANTIC_GATE` explicitly, from a separate verified pre-run repeated twice agreeing to ±0.01; record both. **Catches:** `calibrate_semantic_floor` fires 28 HTTPS embeds at every store open; one blip returns a zero probe, the gate resolves to `None` (semantic-only admission refused for the whole run) **and** the floor falls back to 0.0 (the hash calibration whose mixed-corpus collapse this repo already measured). Neither logs an error. Declaring removes the failure mode instead of detecting it.

**A6 · BLOCKING · Retrieval knobs pinned, including the mode.**
Assert unset-or-default: `UNDERCROFT_FUSION` (must resolve to `bm25` — on `Fusion::Legacy` the blend is hardwired, `lexical_morph` is forced to 0, and `UNDERCROFT_FUSION_WEIGHT` is dead code), `UNDERCROFT_FUSION_WEIGHT`, `UNDERCROFT_TRUST_FLOOR`, `UNDERCROFT_POOL_DIV`, `UNDERCROFT_ADMISSION`, `_ADMISSION_RATE`, `_ADMISSION_LLM`, `UNDERCROFT_WING_PQ_MIN`, `_PQ_PAGE_MIN`, `_FDE_IVF_MIN`, `UNDERCROFT_RERANKER`. Any deviation named in the declared-deviations block. **Catches:** `UNDERCROFT_FUSION_WEIGHT=0.70` is a documented lever that moved FLORES cross-script R@5 from 0–4% to 100%; a stray `UNDERCROFT_FUSION=legacy` produces a materially lower number indistinguishable from a retrieval result.

**A7 · BLOCKING · Fresh volume; one split per vault.**
`docker volume rm`/`create` recorded; pre-ingest `drawers == 0` and `writes == 0` from `/v1/vaults/<id>/stats`. Each split gets its own vault (locomo: 10 wings/876 drawers; personamem: 37/2042), with zero foreign wings. **Catches:** a retried ingest appending a second corpus copy (every id still unique — append index is AUTOINCREMENT — so only the census equality sees it), and cross-split contamination of BM25's IDF, which is global to the vault: wing scoping isolates candidates, **not scores**, so a shared vault makes every LoCoMo lexical score a function of personamem's vocabulary while every isolation gate still passes.

**A8 · BLOCKING · Served-embedder transport is local and pinned.**
`UNDERCROFT_EMBED_URL` resolves to the compose TLS terminator, `UNDERCROFT_EMBED_CA` is the terminator root, the mount is the **project-prefixed** `undercroft_undercroft-embed-tls` (a bare name mounts a fresh empty volume silently). **Catches:** a hosted API quietly answering, which breaks the local-first premise and sends verbatim drawer text off the machine.

**A9 · IMPORTANT · Served embedder is deterministic.** Embed 20 texts 5× through the pinned endpoint; byte-compare. **Pass:** identical, or the report qualifies every determinism/reproducibility claim. **Catches:** a batching runtime returning fp-different vectors, which un-pairs the flat/rich comparison and makes reruns a harvestable source of variance.

## Stage B — pre-ingest (the corpus and what the answerer will read)

**B1 · BLOCKING · Chunking is AMB's, verified by replay.**
Read `CHUNK_SIZE` from the clone. Chunk with cl100k_base, 512, `disallowed_special=()`, no overlap, including the short-circuit that returns the **original string** when a document is ≤512 tokens. **Pass:** totals and the full per-wing vector match the ✓ values (876 with the exact 10-entry vector; 2042 across 37 wings); `''.join(chunks) == content` for 272/272 and 195/195; max chunk ≤512 tokens; 0 U+FFFD; sum of chunk token counts == document token count. **Catches:** a re-implemented chunker, added overlap (free recall inflation), a tail-chunk off-by-one, a boundary that splits a multi-byte character. The per-unit vector is the check — two chunkers can coincide on a total.

**B2 · BLOCKING · Ingested text is `Document.content` verbatim.**
locomo content is `json.dumps(turns)`; assert the drawer stream is that JSON, not a re-rendered `SPEAKER said "…"` form — concretely, `blip_caption` occurrence counts equal between cache and ingest stream. personamem is `[ROLE] text` blocks joined by blank lines. Zero re-serialisation in the driver. **Catches:** this repo's own Defect 2 — a native harness that formatted speaker+text and dropped image captions, which carry 37.9% of gold-evidence turn references.

**B3 · BLOCKING · Wing/room mapping is identity and injective.**
wing == AMB `user_id` byte-for-byte; room == AMB document id byte-for-byte; no trim, case-fold, hash or sanitiser. **Pass:** 272 (resp. 195) distinct rooms, map injective, 0 HTTP 400 "invalid name", 0 ids modified. Note `validate_name` validates `value.trim()` but the drawer stores the **untrimmed** string, so `"conv-26 "` becomes a distinct wing. Assert the distinct save-wing set == distinct search-wing set == distinct query `user_id` set as byte-equal sets, and cross-check against the wing list from `/stats`; 0 drawers in `general`/`inbox`. **Catches:** a sanitiser collapsing two document ids into one room, which makes room→gold_id many-to-one and **inflates gold recall** while census, scope and verbatim gates all pass; and one stray character in a wing name, which makes a whole conversation return 0 hits — auto-failed by AMB with no judge call and no error.

**B4 · BLOCKING · Answerer batch files carry exactly three keys, checked by an independent reader.**
A script that did not write them reads every batch off disk: `set(row.keys()) == {"id","question","context"}` (MCQ shape for personamem), then greps raw bytes for `gold`, `gold_answers`, `gold_ids`, `correct_answer`, `category`, `question_type`, `sample_id`, `speaker_a`, `speaker_b`, `persona_id`, `topic`. **Pass:** exact set equality, zero forbidden tokens. **Catches:** this project's recorded first-attempt defect (gold in the answerer's file); and the subtler one — locomo `meta` carries the literal strings single-hop/multi-hop/temporal/open-domain and both speaker names, while AMB's builder consumes **only** `query_timestamp`. Passing category is a free hint AMB never gives.

**B5 · BLOCKING · Gold string does not reach the answerer outside `context` (locomo only).**
`gold_answers[0]` (str()-coerced) appears in no field but `context`. **PersonaMem: this check is invalid and is explicitly skipped with the reason recorded** — AMB's `query_text` is persona name + user message + all four option lines and `gold_answers[0]` is the full correct option text, so it is legitimately inside `query` for 589/589. **Catches:** gold arriving via a scaffold field — and, on personamem, a well-meaning "fix" that strips options and silently converts MCQ into an open-ended task.

**B6 · BLOCKING · The agent scaffold is published, hashed, word-allowlisted, and identical across every arm.**
Everything the subagent receives that is not AMB's own prompt: role instruction, batching mechanics, output format. Assert it contains none of: guess, be specific, prefer, if unsure, date, concise, confident, list all, generous, lenient. One answerer-scaffold hash and one judge-scaffold hash across main arms, controls and ceiling arms. **Catches:** prompt-template parity hashes AMB's template and the substituted fields; the scaffold sits entirely outside that check, and "always convert relative references to explicit dates" is a score-moving instruction wearing batching mechanics as a costume.

## Stage C — post-ingest (before any query is issued)

**C1 · BLOCKING · Drawer content multiset equals the chunk multiset, by hash.**
Page every drawer out; compare the multiset of sha256(content) and the multiset of (wing, room) pairs against the chunker's output. **Pass:** equal hashes with equal multiplicities. Note ✓ personamem legitimately contains **741 duplicated chunk contents** (2042 chunks, 1301 distinct, every duplicate appearing exactly twice); locomo has 876 distinct. A "distinct content == drawer count" rule is wrong on personamem — the requirement is multiset equality, not distinctness. **Catches:** substitution that preserves counts (a prepended session header, AMB's `Document.context` string written into the drawer — whose session ordinal is genuinely useful on temporal questions — or one chunk lost and another duplicated).

**C2 · BLOCKING · Census conservation and per-wing vector, run before the first query.**
`drawers == writes == chunk count` (876 / 2042); per-wing counts match the ✓ vector; rooms == 272 / 195; wings == 10 / 37; every save returned HTTP 200 with `created:true, deduped:false, quarantined:false`; no request body carried `dedup_threshold`; max drawer ≤512 cl100k tokens. **Catches:** deterministic-id overwrite (two chunks colliding on (wing, room, source, chunk_index)), a 202 quarantine diversion (hard-excluded from retrieval, id still returned), dedup collapsing near-identical dialogue chunks, a whole-document drawer smuggled in beside the chunks (one k-slot delivering ~10× the tokens), and a retried POST creating a second drawer with identical content that gets two chances at a k=10 slot.

**C3 · BLOCKING · Normalization delta is predicted, not discovered.**
The REST save path runs `normalize_content` (Prose): per-line `trim_end`, blank runs >2 collapsed, CRLF→LF, lone control chars removed, outer newlines trimmed — with a fence-toggle exemption. Re-implement it locally, run it over every chunk, and compare stored bytes against the **local prediction**, then separately count `stored != posted`. **Pass:** stored == predicted for 876/876 and 2042/2042; `stored != posted` equals the predicted count exactly — ✓ reference: **1/876 locomo (1 character), 111/2042 personamem (795 characters)**; every difference whitespace-only; 0 chunks empty after normalization (which would 400 and be silently lost). The fix for a mismatch is never to pre-normalize the chunks or disable normalization. **Catches:** the naive "100% byte-identical verbatim recovery" gate, which **fails by construction on personamem at a 5.4% rate**; the engineer's two natural repairs — waive the check, or pre-trim the chunks — respectively delete the check and silently alter AMB's bytes on 292 leading-whitespace locomo chunks.

**C4 · BLOCKING · Recorded embedder identity is the served model — read from the right place.**
Read `embedder` from `GET /v1/vaults/<id>/export`'s manifest **and** `SELECT value FROM meta WHERE key IN ('embedder_name','embedder_dim')`; both must agree on `http:<model>` and the served dimension (1024 for bge-m3), never `undercroft-hash-v3`/384, with no migration or identity-mismatch warning at open. **`/v1/vaults/<id>/stats` cannot serve this gate — its JSON is hand-projected and carries no embedder field.** **Catches:** exactly the fallback this project was just bitten by (`UNDERCROFT_EMBEDDER=http` honoured by the CLI resolver and absent from the server's, so `remember` used the served model and every `/v1` write did not). Worth 3.2–4.2pp on this corpus, i.e. plausible and wrong.

**C5 · BLOCKING · Dimension proven at rest, trusting no self-report.**
`SELECT DISTINCT length(embedding) FROM drawers`. **Pass:** exactly one value == 46 + dim (1070 for 1024-d; 430 means the hash embedder). Cardinality >1 means two vector spaces in one corpus. **Catches:** a fallback that happened partway through ingest, and a vault recording one identity while storing another space's vectors.

**C6 · BLOCKING · Zero failed embeds, counted from process start.**
Grep the engine's stderr from **container start** (not first save) through the end of retrieval for the degradation line containing `storing a zero vector`; record the final counter if any. **Pass:** exactly 0. Any non-zero count forces re-ingest of the affected drawers; it is not a footnote. **Catches:** three distinct windows that a first-save-onward grep misses — the 28 calibration embeds at open (sets gate=None and floor=0.0 for the entire run), ingest blips (drawer stays lexically findable and semantically dead), and **query-time** failures (zero query vector, cosine 0 against everything, a full non-empty page ranked by BM25 alone). `HttpEmbedder::failures()` is not surfaced on `/v1`, as a gauge, or in any metric — stderr is the only channel.

**C7 · BLOCKING · Positive/negative retrieval controls, no model involved.**
(a) Verbatim recovery: for ≥400 drawers per split, search with the drawer's own **stored** content, own wing, limit 10 → `hits[0].id == drawer id`, **≥99%** (<95% is a hard stop; 95–99 requires naming the colliding chunks), and the returned `content` byte-equals the stored content. (b) Paraphrase probe: 20 hand-written probes per split sharing no content word with the target → ≥18/20 in the top 10, and ≥1 hit across the whole run admitted with `lexical_exact == 0 && lexical_morph == 0` (proof semantic-only admission is live). (c) Negative: the same verbatim query scoped to a different wing returns 0 in-scope evidence. Re-run all three at arm end. **Catches:** a lost/overwritten drawer, a wing built from the wrong field, a query field that never reached the engine, an id scheme that changed between ingest and probe — and a run that claims "served bge-m3" while measuring keyword search because the gate resolved to None.

**C8 · IMPORTANT · Admission proven off *and* proven inert.**
Variables unset (A6) plus: 0 HTTP 202, 0 `quarantined:true`, `quarantine-pending` absent from the wing list, **and** the tier-1 detector run offline over all 2918 chunks with per-class trips, flagged fraction and corpus max score recorded. **Pass:** 0/2918 trips, headroom recorded. **Catches:** personamem chunks open with `[SYSTEM] Current user persona: …` — instruction-shaped preamble, exactly the hard-negative class the 0.45 threshold was calibrated against at 0.369. Proving headroom beats proving a flag was unset.

**C9 · IMPORTANT · Vault integrity and index generations frozen.**
`verify` clean after ingest and after the last query; record `PalaceStats.codebooks` generations at the first and last query of each arm. **Pass:** 0 integrity failures; generation counters identical across an arm (ingest everything, build once, then query). **Catches:** rows failing their HMAC on read and being skipped (a quietly shrinking corpus), and a retrain firing mid-arm so early and late units are answered under different candidate generation.

## Stage D — retrieval (one frozen pass, then nothing touches the vault)

**D1 · BLOCKING · Search request body is pinned to one shape.**
Hash the key set of every request. **Pass:** cardinality 1, exactly `{query, wing, limit, ranked_at}` for personamem and `{query, wing, limit, ranked_at, as_of, language}` for locomo. Specifically zero requests carrying `room`, `room_cap`, `offset`, `kind`, `min_trust`, `vector`. **Catches:** `room` is oracle retrieval wearing a scope parameter — locomo's room **is** the gold_id. `room_cap` spreads k across rooms and would materially raise a recall metric measured at room granularity. `kind` returns 0 hits on every query (our saves declare none) and AMB auto-fails all of them with no judge call.

**D2 · BLOCKING · `ranked_at` pinned; `as_of` byte-equals the injected CURRENT DATE.**
Every request carries the same explicit RFC-3339 `ranked_at`, ≥ the last save's `filed_at`, identical across every arm and control, echoed byte-for-byte in every response. Separately, locomo rich-arm `as_of` == the exact `query_timestamp` string that arm injects as CURRENT DATE (faithful arm: the cached lexicographic-max value; corrected arm: the true last-session date), and the flat and rich arms of one query use the same `as_of`. `language` declared. **These are two different fields and both sources in the candidate set were half right:** `ranked_at` drives the recency term (0.10 weight, 30-day half-life, defaults to `now_utc()`), `as_of` drives `elapsed_*`/`same_frame`. **Pass:** 100% on both; a single `as_of`/CURRENT-DATE disagreement voids the faithful arm. **Catches:** retrieval becoming a function of wall-clock time (arms hours apart are not the same system, and the resulting flaky determinism gate invites a rerun, which feeds the ratchet); and a corrected arm hiding inside the faithful one — correctly-computed intervals under a wrong stated "today", worth real points on 321 temporal queries.

**D3 · BLOCKING · One immutable retrieval pass, phase-separated.**
Retrieval writes ONE JSONL keyed by query id (request body, ordered hit ids, full raw response, `ranked_at`, `retrieve_time_ms`). sha256 it before the first answering call and after the last judging call of both arms. Run the scored pass with `UNDERCROFT_READ_AUDIT=chain`, restart the engine (read records anchor at next open), and assert `read/*` record count == query count **exactly** (1540, then 589) and drawer-`writes` unchanged. Answering-phase wall-clock windows carry zero search requests. **Pass:** four identical sha256s; exact read count; `writes` constant across all arms; one container id per arm. **Threshold conflict resolved:** enable read auditing for the scored pass and take `avg_retrieve_time_ms` from a separate unaudited replay, footnoted — a retrieval-count proof is a validity gate, latency is a reported quantity, and only the reported quantity can carry a footnote.

**D4 · BLOCKING · Flat context is byte-reconstructible from the rich payload.**
Recompute `"\n\n".join(f"## Memory {i+1}\n" + h["content"])` from the stored raw response and sha256-compare against the string handed to the flat answerer. **Pass:** 1540/1540 and 589/589. Additionally: for the ✓ 112 chunks known to differ from their posted form (C3), assert the prompt carries the **engine-returned** form and never the pre-ingest form. **Catches:** the whole two-arm risk in one check — a second retrieval, a different order, a dedup on one side, a post-hoc edit, or an answerer reading pre-ingest bytes the engine never scored.

**D5 · BLOCKING · Wing scoping applied and zero cross-unit leakage.**
Every hit's `wing` == the requested wing, across all ~15,400 + ~5,890 hits. Plus: for 20 sampled queries, the identical search under a different wing surfaces no gold chunk. **Pass:** cross-wing hit count 0. **Catches:** one conversation answering another's questions — a live failure in AMB's own bm25 baseline (falls back to the global index when the user subset is empty), and personamem is especially exposed because it declares no isolation unit.

**D6 · BLOCKING · k discipline and full pages.**
`limit == 10` on 100% of requests; `len(hits) == 10` on 100% of queries; `next_offset == len(hits)` (proving offset 0); max hits over the run == 10. Any short page is listed individually with its per-channel evidence (`lexical_exact`, `lexical_morph`, `semantic`) and the gate value, and the headline waits until the cause is named. **Pass condition is exact-10 because the smallest wing is 51 (locomo) / 40 (personamem) ✓ — far above k.** **Catches:** the `hits.retain` relevance filter running **before** `truncate(depth)`, so a too-high gate or a dead lexical channel silently shrinks the page; and a paging loop concatenating pages into what the record calls one response. Zero hits go straight to AMB's `elif not answer_result.context` auto-fail with no judge call and no error.

**D7 · BLOCKING · Rich-payload key set is closed and every derived field is self-referential.**
Per hit, key set exactly the 20 the route emits; top level exactly `{hits, next_offset, ranked_at}`. Every `entities` string and every `time_mentions[].text` is a literal substring of **that hit's own** `content`; every date field parses. **Catches:** retrieval arriving through a field nobody re-read — a future cross-drawer summary, KG neighbourhood or corpus statistic shipped in a metadata field's name is extra retrieval.

**D8 · BLOCKING · Rich-arm derived fields are actually populated (locomo).**
`content_date` non-null on 100% of locomo hits (all 272 documents carry a timestamp ✓); `elapsed_days`/`_weeks`/`_months`/`elapsed`/`same_frame` non-null on 100% of locomo rich hits (they are computed only when `as_of` **and** `content_date` are both present); `semantic` non-null on every hit in every arm. **PersonaMem: `content_date` null on 100% by construction ✓ (0/195 timestamps) — no `content_date` sent, no `as_of` sent, no temporal claim made.** **Catches:** a "rich" arm that is really content+scores because `as_of` was never sent — the delta then measures JSON re-encoding (~1.05× flat tokens) and the report names fields the model never saw.

**D9 · BLOCKING · Retrieval determinism.** Re-run ≥150 queries against the untouched vault; identical hit-id lists and order for 100%. Any difference is explained (retrain, non-deterministic endpoint) before any downstream number is read.

**D10 · BLOCKING · Retrieval errors never become wrong answers.** Count non-2xx responses and transport errors; the driver exits non-zero if either is non-zero and both counts print even at zero. AMB's own runner policy — retry with backoff, then **raise** — is the one to copy, not `hindsight.py`'s swallow-and-return-empty. **Pass:** 0 errors reach the scorer, or an explicit separate line "N queries scored 0 because retrieval failed", never folded into accuracy.

**D11 · IMPORTANT · Prefilter state and scale disclosure.** At ~88 (locomo) / ~55 (personamem) drawers per wing the scope fits the hydration budget `max(256, depth·32)` and `UNDERCROFT_WING_PQ_MIN`=4096 is never reached, so a wing-scoped query is an **exact scan with no prefilter**. Record the path (optionally `UNDERCROFT_SEARCH_TRACE=1`) and state that this run says nothing about PQ/IVF/FDE candidate generation, prefilter recall, or behaviour at 10⁵–10⁶ drawers.

**D12 · IMPORTANT · Retrieval budget as a share of the isolation unit, distributionally.**
Per query, k ÷ that query's own wing chunk count; report min/median/max per dataset, not a corpus average. ✓ locomo: 8.6 / 10.9 / 19.6%. ✓ personamem: 15.6 / 17.5 / 25.0%. **Flag at a median of 25%:** at that point the task is reading comprehension and the accuracy is not reportable as a retrieval result. Apply the same computation to the k\*≈20 token-matched control (17.2 / 21.9 / 39.2%), which is itself inside the warning band. **Catches:** this project's own uninterpretable k=30 run at 94.4%; a corpus average hides it, because conv-30 has 51 chunks and hands over a fifth of itself at k=10.

**D13 · IMPORTANT · Empty-hit accounting per arm.** Count `len(hits)==0` per arm; the count must be **identical across arms** (they share one pass, so a difference proves the pass was not shared); those rows are scored incorrect with AMB's own reason string and stay in the denominator. Report accuracy over all queries and over the non-empty subset. Expected 0 here given D6.

## Stage E — answering

**E1 · BLOCKING · Prompt parity, generated from the clone at run time.**
Call the clone's `build_rag_prompt` and hash it; compare against the prompt actually sent, ≥50 queries per arm. CURRENT DATE line present on 1540/1540 locomo and 0/589 personamem. Rich arm substitutes `json.dumps(raw_response)`; flat uses the `## Memory {i}` assembly; a falsy `raw_response` falls back to flat. Never copy AMB prompt text into the undercroft repo. **Catches:** the documented defect that produced a publishable-looking 67.9% — prompts written by us rather than read from AMB.

**E2 · BLOCKING · Each arm actually received its own regime, and rows are arm-bound.**
Every flat prompt contains `## Memory 1` and not `"hits"`; every rich prompt the converse. Every answer and verdict row carries an `arm` field plus the sha256 of the exact prompt it was produced from; recompute that hash from the frozen retrieval pass and compare; the two arms' answer sets are not byte-identical. **Catches:** `ctx = json.dumps(raw) if raw else context` is a truthiness test — an empty payload silently falls through to flat, blending two regimes under one number; and transposed arms, which point the delta the wrong way with no count, schema or id anomaly anywhere (query ids are identical across arms, so every id-based reconciliation passes on swapped files).

**E3 · BLOCKING · PersonaMem has no rich arm, proven.**
sha256 over the sorted list of (query_id, full prompt) for both arms must be **byte-identical** for all 589. PersonaMem's `build_rag_prompt` never reads `_raw_response`. **Pass:** identical, or no personamem "rich" number is reported at all. **Catches:** reporting a personamem flat/rich delta, which cannot exist under a faithful replication and would be measuring the harness.

**E4 · BLOCKING · Answer schema conformance, failing closed.**
Open: `{reasoning, answer}`, both required, only `answer` judged. MCQ: `{reasoning, choice}`. Normalise MCQ exactly as AMB does — `strip().lower().strip("(). ")[:1]` — replayed against the clone's function on a 50-row sample with identical outcomes. **Pass:** 0 empty `answer` fields; 589/589 personamem answers normalise into {a,b,c,d}; un-normalisable answers are counted, **reported, and scored incorrect — never dropped and never coerced**. **Catches:** AMB's own fail-open (`gemini.py`'s last resort returns `{k: last_text}`, stuffing prose into `answer`), prose-instead-of-a-letter losing points AMB's schema-constrained pipeline never loses, and denominator shrinkage from silent drops.

**E5 · BLOCKING · Batch reconciliation and single-attempt accounting.**
Answered batches == expected; answers per batch == batch size for **every** batch (printed per batch); unique answered ids == 1540 / 589; returned id set == submitted id set, never positional matching. Maintain an append-only attempt ledger: one row per (arm, batch, attempt, id-list sha256, consumed y/n); exactly one consumed attempt per (arm, batch); no id in two consumed attempts; every consumed id-list hash matches the planned manifest. **Catches:** the observed failure — one agent returning 19 of 20, invisible at 1-in-1540 to every aggregate check — and a re-sliced retry that answers one query twice under different batch-mates while another is never answered, which reconciles perfectly if the harness keeps last-row-per-id.

**E6 · BLOCKING · Exactly one scored attempt per query; no failure ratchet.**
`max(attempt_index) == 1` for every query; answer generations == query count; **zero** use of `--only-failed`, `--skip-answer`, `--skip-retrieval`, `--skip-ingested`, `--query-id` or any harness equivalent. The results file did not exist when the arm started (record creation time vs arm start); every row's timestamp falls inside the arm window; zero extra ids. **Exception, capped:** a schema parse failure may be regenerated **once**, logged as attempt 2 with the parse error; regenerated rows ≤1% of the arm, their accuracy reported separately; a second failure is scored incorrect. **Catches:** the strongest available attack. AMB's `_save` merges by query_id with new results winning, and `--only-failed` re-rolls exactly the incorrect rows. With non-temperature-0 subagents that is a monotone ratchet worth +5–8pp over three passes, and the output file is internally consistent — every denominator, uniqueness, per-category and completeness gate passes on a fully ratcheted file. Nothing else counts attempts.

**E7 · BLOCKING · Context arrival probe by batch position.**
Build a probe batch in each arm's **exact shape and size** (20 rows, same format, same per-row token budget — rich prompts average ~8,930 cl100k tokens, so a rich batch file is ~180k tokens) where every row's context carries a unique planted nonce and the question asks for it. **Pass:** 20/20 recovered at every position in both the flat-shaped and rich-shaped probe; max real batch-file token count recorded and below the agent's read limit; probe re-run at arm end. Separately tabulate real accuracy and parse-failure rate by within-batch position 1..20 and assert the last object of every batch is structurally complete. **Catches:** silent truncation of a long rich batch — the agent reads the first N bytes and answers all 20 anyway, returning 20 well-formed answers. Count, id, schema and judge gates **all** pass, and the result reads as "rich context did not help".

**E8 · BLOCKING · Answerer positive control.** 20 synthetic one-drawer contexts each holding a single unguessable planted fact, in the exact `## Memory 1` shape and the dataset's own prompt. **Pass:** 20/20. **Catches:** an answerer ignoring the context block entirely — which the no-memory arm cannot distinguish from "context was useless".

**E9 · BLOCKING · Both arms share batch composition, model, scaffold and schema.**
sha256 of the ordered per-batch id list, the model id (explicitly pinned, not inherited from the session), the instruction text and the response schema, compared arm to arm. **Pass:** all equal; the only permitted difference is the `{ctx}` substitution. **Catches:** differing cross-query leakage between arms, or a drifted model tier — either makes the delta meaningless while both arms individually look well-run.

**E10 · IMPORTANT · Answer-field length and enumeration budget.** Report cl100k length distribution (median/p95/max) of `answer` per arm and control, plus mean distinct dates and capitalised spans per answer, against the gold-length distribution. Count answers <3 chars and pointer answers ("see above"). **Flag:** if the main arm's median answer length exceeds the no-memory control's by >2×, the arms are not comparable until the difference is attributed. **Catches:** shotgun answering under LoCoMo's explicit generosity instruction — five plausible dates and six entities passes far more often at zero retrieval quality, and schema/batch/prompt gates are all blind to it. Also catches the reverse (working in `reasoning`, a terse pointer in `answer`), which is a pure false-negative.

## Stage F — judging (**locomo only; personamem has no judge**)

**F1 · BLOCKING · Judge prompt parity and invocation count.**
Use LoCoMo's own `build_judge_prompt` (generous grading, `gold_answers[0]` only, date leniency, the "answer cannot be found" edge case), **not** `judge.py`'s default strict prompt. Judge calls == 1540 for locomo and **== 0 for personamem** (MCQ is exact-letter, no judge at all). Assert the argument order — `GeminiJudge.score(query, answer, gold_answers, …)` calls `prompt_fn(query, gold_answers, answer)`, swapped relative to its own signature — so the rendered gold line equals `str(query.gold_answers[0])`, the candidate line equals the answerer's `answer`, and exactly one gold appears. The 6 ✓ integer golds are str()-coerced, not dropped. **Catches:** the strict prompt systematically disagrees with LoCoMo's on abstentions; swapping gold and candidate inverts a deliberately asymmetric instruction and makes the judge harsher; judging MCQ replaces the most objective number in the run with an LLM opinion.

**F2 · BLOCKING · The judged candidate is the `answer` field only, and the judge is blind.**
sha256(candidate) == sha256(answer) for 1540/1540; the row's `reasoning` appears nowhere in any judge input. Judge payload key set exactly `{id, question, gold, candidate}`; grep judge inputs for `flat`, `rich`, `corrected`, `control`, `oracle`, `baseline`, `## Memory`, `hits`, `semantic`, `score`, `wing`, and for 200 distinct 60-char corpus shingles. No judge batch contains two rows with the same query_id or rows from more than one arm. **Catches:** reasoning-as-candidate (a paragraph of hedged alternatives handed to a generous judge — the single easiest honest mistake in the step); a judge that can see which arm it is grading; and comparative grading of one query's flat and rich answers in the same batch, which would manufacture the exact delta the run is measuring.

**F3 · BLOCKING · Verdict reconciliation and a fixed denominator.**
Every verdict is `{correct: boolean, reason: string}` parsed structurally; every verdict id is in that batch's **answer** id set; every answered id gets exactly one verdict; rejections counted and reported even at zero; a rejected or unparseable verdict stays in the denominator (re-run once per E6, else scored incorrect with the count stated). Accuracy denominator == 1540 exactly. The ✓ 9 empty-`gold_ids` and 6 integer-gold rows are present and counted (excluded only from **recall**). **Catches:** AMB's own fail-open (`bool(data["correct"])` on a non-empty raw string = CORRECT, so every judge hiccup is a free point); the observed judge padding — asked for 20 verdicts it produced 20 by duplicating an id, a grade for a question nobody answered, caught only by id reconciliation; and AMB's published `cognee` row, 152 of 1540 queries presented as an 80.3% result.

**F4 · BLOCKING · Judge positive control.** Hand the judge the verbatim gold (str()-coerced) as the candidate for ≥100 queries. **Pass:** 100% correct. Any failure is a hard stop — a judge that rejects its own gold depresses every arm non-uniformly and shrinks every lift.

**F5 · BLOCKING · Judge negative control (mismatched gold).** A different query's gold as candidate, ≥100 queries. **Pass:** ≤5% correct.

**F6 · BLOCKING · Judge shotgun control.** For ≥150 queries, synthesise a candidate from that query's **own retrieved context alone**, with no reference to the question: the 5 most frequent capitalised spans plus every date string, phrased as a list of possibilities. **Pass:** ≤10% correct; >20% means the judge cannot distinguish an answer from a context dump and no accuracy from it is reportable. **Catches:** what F5 structurally cannot — F5's off-topic candidate is trivially rejectable, while the real risk is a judge accepting any on-topic enumeration drawn from the right conversation.

**F7 · BLOCKING · Abstention control, with its premise re-measured.**
✓ 0 of 1540 locomo golds are abstention-shaped, so LoCoMo's "information was never mentioned ⇒ correct" edge case never legitimately fires on this split. Re-measure that (do not assume it), then: a fixed refusal string as candidate for ≥100 queries scores ≤2% correct, and judged-correct abstentions across every real arm == 0. If a future split has abstention-shaped golds, those ids are exempted **by id** with the list published — never a blanket rule. **Catches:** a lenient judge crediting refusals (which would inflate the no-memory arm specifically and destroy every lift), and an engineer enforcing "abstentions correct == 0" **against AMB's own judge prompt**, i.e. deviating from the protocol to satisfy a gate.

**F8 · BLOCKING · Judge self-agreement is the run's noise floor.**
Re-judge a fixed 200-verdict sample (balanced correct/incorrect) in a second independent pass, same prompt and model. Report raw agreement and Cohen's κ. **Pass:** raw agreement ≥95%; **no delta anywhere in the run — flat vs rich, faithful vs corrected, arm vs prior run — may be described as a finding unless it exceeds this disagreement rate** as well as the D-stage statistical threshold (G2). **Threshold conflict resolved:** ≥95% raw agreement is the gate; the measured flip rate (not a fixed pp figure) is the floor.

**F9 · IMPORTANT · Judge two-sidedness and calibration audit.** Read ≥30 graded-correct and ≥30 graded-incorrect (question, gold, answer, reason) tuples; hand-audit ≥100 stratified rows (≥25 per category, oversampling multi-hop at n=96); re-judge that sample with a second independent judge. Report precision/recall against the human audit and judge-vs-judge disagreement. State explicitly that answerer and judge are the same model family, a deviation from AMB (groq answer / gemini-2.5-flash-lite judge). **Catches:** a judge lenient toward its own model's phrasing — the entire margin over a comparison row can live here with no other symptom.

## Stage G — controls, statistics, reporting

**G1 · BLOCKING · Model-free gold recall (locomo only), computed non-degenerately.**
Map each hit's `room` to an AMB document id; per query (denominator ✓ 1531 — the 9 empty-`gold_ids` excluded **and printed**) compute session any-gold@10 and full-coverage@10, overall and per category, with explicit numerator/denominator. Sanity-check the implementation three ways on 150 queries: wing-based must come out **exactly 100%**, drawer-id-based **exactly 0%**, and the reported room-based figure strictly between and never exactly 0.0 or 100.0. Then count queries judged **correct with no gold document in context** and report it as a fraction of total. **Catches:** the single strongest detector of a retrieval bug hidden behind a competent LLM — accuracy exceeding recall@10 means the answerer is scoring from priors or intra-batch leakage. Also catches the two degenerate recall implementations, both of which look like real results ("retrieval is broken" / "perfect recall"). **PersonaMem is excluded: ✓ gold_ids ÷ documents-per-user == 1.000 for 589/589 — a 100% recall row there is arithmetically guaranteed and misleading in both directions.**

**G2 · BLOCKING · Cluster-robust uncertainty; paired tests for paired arms.**
Every interval is a bootstrap over the **isolation unit** (resample the 10 conversations / 37 contexts with replacement, 10,000 draws), never a binomial SE over queries. Flat vs rich, faithful vs corrected, and every arm-minus-control lift are **paired** — report McNemar's p with the discordant counts, plus the cluster bootstrap of the paired difference. No superiority claim unless the CI of the difference excludes zero **and** the delta exceeds F8's floor. **Threshold conflict resolved in favour of the cluster bootstrap:** the "n=1540, se=1.0pp" formulation treats 1540 questions about ten conversations as independent; the effective sample size is nearer 10 than 1540, and encoding the binomial SE as the threshold actively authorises 2–3pp claims the data cannot support.

**G3 · BLOCKING · Controls exist, are regime- and config-matched, and are computed on identical id sets.**
Required arms, each in the **same context regime** as the arm whose lift it serves, with every non-controlled variable byte-identical (model, judge, batch size, scaffold, k, security level, embedder, fusion mode/weight, semantic floor/gate):
- **no-memory** — empty context, same prompt including the CURRENT DATE line. **Must bypass AMB's `elif not answer_result.context` auto-fail and be judged**, recorded as a declared deviation: AMB's shipped `none` provider scores exactly 0.0 by construction under rag mode and measures nothing; reproducing that faithfully invents a 100-point lift. Regime-independent, so one arm serves both.
- **wrong-scope** — a fixed **derangement** (sorted unit ids rotated by 1), recorded in the manifest; 0 self-wing hits; every wrong wing ≥40 drawers.
- **random-in-wing** — correct wing, k=10 drawn by keyed uniform sample from that wing's enumerated drawers (seed recorded). Verify the sample is actually random by its gold containment against the closed-form prediction (~39.8% ±5pp) — `GET /drawers` returns deterministic order and taking the first 10 is session_1/session_2, which are disproportionately gold-bearing.
- **per-query oracle ceiling** (ours, labelled) — context = exactly this query's gold chunks in gold order, same assembly, no retrieval; the 9 empty-gold queries scored incorrect and counted.
- **token-matched flat k\*** (k\*≈20) on a category-stratified ≥300-query subsample.
- **bm25** — AMB's own provider, unmodified from the clone, through the identical pipeline.

Every lift is computed on the **intersection of id sets**, `|A| == |B|` with equal id sets; if a control ran on a stratified subsample, the main arm is recomputed restricted to that subsample. **Catches:** cross-regime subtraction (attributing structured-metadata benefit to retrieval), main-full minus control-subsample, and an auto-failed no-memory arm reading 0% and making every lift look enormous.

**G4 · IMPORTANT · The lifts themselves, with interpretive bands.**
Report unconditionally, with G2 intervals: locomo main−no-memory, main−wrong-scope, main−random-in-wing (the only control that isolates **ranking** from **scoping**, and the one most likely to fire — 11.7% of a conversation at k=10 already contains gold ~39.8% of the time), main−bm25, main÷oracle. Bands, stated as interpretation and **not** as validity gates: no-memory lift <30pp ⇒ no memory-layer claim; <15pp ⇒ the run measured the answerer; wrong-scope lift <25pp ⇒ scoping is the only contribution; random-in-wing lift <15pp ⇒ no retrieval-**quality** claim, only a scoping claim; oracle <60% ⇒ the bottleneck is the model roles and no finer-resolution delta is interpretable. **Threshold conflict resolved deliberately:** the candidate set proposed making these lifts BLOCKING validity gates. They are results, not validity checks — gating publication on a result is precisely what creates pressure to re-run until it passes (E6's ratchet). Publication of the lift is blocking; its magnitude is interpretation. Also report `wrong_scope ≥ no_memory − 5pp` (below that, irrelevant context is actively misleading the answerer, which is a prompt property inflating the apparent main-arm lift).

**G5 · IMPORTANT · Rich-arm token accounting, both ways, and attribution.**
Report per arm the cl100k count of the **prompt actually sent** (mean/median/p95) — reference ✓-adjacent measurement: flat ~4,394, rich ~8,930, ratio 2.03× — **and** the AMB-comparable flat count, with one line stating why they differ (`runner.py` sets `context_tokens = count_tokens(answer_result.context)`, the flat string, in **both** arms, so every raw-response provider on AMB's leaderboard has its cost column understated the same way). No cost or efficiency claim may be derived from AMB's field. Decompose the rich payload (flat / id+content JSON ≈1.05× / full rich ≈2.03×), so it is visible that roughly half the rich prompt is engine-computed signal rather than re-encoded drawer text. Enumerate exactly which extra fields the rich arm carries and report the arm delta **per category**; replace "richer context helps" with which fields and which category moved. Two ablations on temporal + multi-hop: (a) strip `time_mentions`/`elapsed_*`/`same_frame`/`occurrences`; (b) strip `room`/`wing` — `room` is `conv-26_session_7`, i.e. the session **ordinal**, which the flat regime cannot see and which is directly useful on 417 queries. Report both deltas.

**G6 · BLOCKING · Faithful and corrected timestamp arms kept separate, and the corrected arm changes exactly one variable.**
Faithful arm reproduces AMB's `query_timestamp` byte-for-byte from the cache, verified to carry the defect signature (the lexicographic-max session date). Diff the two arms' query files field by field: `query_timestamp` is the **only** field that differs, on 100% of rows. The faithful arm is the headline; the corrected arm is labelled "ours, not comparable" and is never substituted. Publish the ✓ skew: early on 10/10 conversations by 96–203 days. **PersonaMem is out of scope — ✓ 0/589 query_timestamps and its builder ignores them.**

**G7 · IMPORTANT · Future-dated evidence and inverted elapsed arithmetic on the faithful arm.**
✓ 182/272 documents (66.9%) are dated **after** the injected timestamp and ✓ 1075/1540 queries (69.8%) have at least one gold document after it. Since `elapsed_days = days_between(content_date, as_of)`, roughly two-thirds of faithful rich-arm hits carry a **negative** elapsed and an inverted `elapsed` phrase. Count and publish the negative-elapsed fraction per query, overall and per category, beside the faithful-rich vs corrected-rich delta. **Catches:** the largest arm-specific undercount in this design — the faithful arm hands the answerer date arithmetic that is signed wrong on most hits, depressing the rich arm specifically on the temporal category, and it looks exactly like the engine's date resolver being bad.

**G8 · IMPORTANT · The flat arm's temporal ceiling is measured, not assumed.**
A LoCoMo document's date lives in `Document.timestamp`, never in `content`. Publish: documents whose content contains any 4-digit year, temporal-category golds occurring literally in their own gold documents, and the **per-query oracle ceiling run in the flat regime**, temporal row. If flat-oracle temporal ≈ flat-measured temporal, the shortfall is the **context format**, not retrieval quality. **Catches:** charging the engine for 321 of 1540 queries (20.8%) that ask for a date from a flat context which structurally cannot contain one.

**G9 · IMPORTANT · Accuracy conditioned on gold presence (locomo).** Split all 1540 verdicts three ways — all required gold in context / partial / none — and report accuracy and count in each; the three counts sum to 1540. **Catches:** reporting memory+reader as one number. The prior run here found 104 of 189 failures had **every** required document in context.

**G10 · BLOCKING · Per-category tables joined on id, with n and intervals.**
Group by `meta.category` (✓ top-level `category` is None on 1540/1540) and by `question_type` for personamem; every table produced by joining result rows to the query table **on id**, never by position and never by re-reading a separately-filtered file. **Pass:** buckets partition the arm's id set exactly (union == id set, pairwise disjoint, counts ✓ 841/321/282/96 and ✓ 139/129/99/93/57/55/17); zero rows in an unknown/None bucket; every sub-row carries n and a Wilson interval widened by the cluster bootstrap; multi-hop (n=96) and `recalling_facts_mentioned_by_the_user` (n=17) carry an explicit "not interpretable alone" label. **G11 · IMPORTANT · Per-wing raw numerators.** A RAW line per conversation with exact numerator and denominator for every metric; sum of per-wing numerators == overall numerator. Overall figures are sums of raw counts, never means of per-conversation percentages.

**G12 · BLOCKING · Manifest-field parity and the run ledger.**
Emit every AMB leaderboard field per arm (dataset, split, category null, provider, run_name, mode, oracle false, total_queries, correct, accuracy, ingestion_time_ms, ingested_docs **in AMB's unit** — 272 / 195 documents, with our chunk count as an additional field — avg_retrieve_time_ms with the answering concurrency stated, avg_context_tokens, answer_llm, judge_llm, description). **G13 · BLOCKING · Non-comparability block, stated once and in full.**
In one place: both substituted model roles and their versions; batched answering (AMB answers one query per schema-enforced call) with E7/G14's measured contamination bound; k=10 against whichever baseline is quoted (AMB's hybrid-search/qdrant rows use 50); the prompt-path split — **the flat arm is the regime AMB's bm25-style baselines were answered from, the rich arm is the regime every commercial provider (hindsight, mem0, cognee, supermemory) was answered from**, because LoCoMo's builder substitutes `json.dumps(raw)` whenever a provider returns one; chunk size and ingest granularity; the served bge-m3 embedder and its transport (not the shipped default); every non-default `UNDERCROFT_*`; the rejected-verdict count; the absence of `room_cap` as a deliberate faithfulness choice; and the explicit statement that these numbers are comparable neither to AMB's published rows nor to this repo's prior 87.6% — and that if more than one variable moved between two runs, **no delta is attributable to any single one**. # RESIDUAL RISK — failure modes NO gate above catches

1. **Pretraining contamination of the answerer.** LoCoMo and PersonaMem are public. A2/A9 stop live lookup; nothing stops memorisation. The no-memory control is contaminated identically, so the **lift** is protected but the **absolute** is not — and a model that has seen the QA pairs will inflate both arms and the control together, compressing every lift toward zero rather than exaggerating it. Direction of the bias is therefore unknown, not merely bounded.
2. **Judge sympathy for its own family's phrasing.** F4–F9 bound gross failure (rejecting gold, accepting anything, accepting a context dump, disagreeing with itself). They cannot detect a judge systematically ~2pp more generous to answers written in the style it writes. The human audit sample (n≈100) is far too small to resolve 2pp.
3. **Ten clusters.** G2 makes the uncertainty honest; it cannot make it small. Any locomo claim finer than a few points is unsupportable and no gate can change that.
4. **A silently wrong served model.** C4–C7 prove the identity string, the dimension at rest, non-zero vectors, determinism and 18/20 paraphrase recovery. A wrong checkpoint served under the right name passes all of it; the paraphrase probe is 20 hand-written items and would have to be badly wrong to fail.
5. **Errors common to arm and control cancel invisibly.** Every lift is a difference. A systematic harness defect applied identically to main, no-memory, wrong-scope and random-in-wing (say, a context-assembly quirk) is subtracted out of every lift and shows up in no gate. Only the absolute numbers would carry it, and those are the numbers we trust least.
6. **Correctness of the rich arm's derived fields is never checked.** D7/D8 prove the fields are present, self-referential and populated; G5's ablation proves they move the score. Nothing verifies that a resolved date is the *right* date. A confidently wrong `elapsed` phrase would be scored as a memory-layer capability.
7. **LoCoMo's gold annotations are incomplete.** Its "single-hop" label carries multiple gold sessions; G1's recall, G9's conditioning and G3's oracle ceiling all inherit that error, which is why main can legitimately exceed oracle. The report can flag the ratio but cannot correct it.
8. **The scaffold word-allowlist (B6) is a blocklist.** It proves the scaffold lacks ten named steering words. It cannot prove neutrality.
9. **The run ledger (G12) and attempt ledger (E6) are discipline, not proof.** The engine's read-record count bounds retrievals **per vault**, but a fresh vault resets it, and a deleted ledger leaves no trace. Nothing cryptographically prevents an unpublished earlier execution.
10. **Batching contamination is bounded, not eliminated.** G14 estimates it from a ≥300-query subsample; the bound has its own interval, and the residual sits inside the headline.
11. **The `ranked_at` pin (D2) freezes recency but not the wall clock's other effects** — a served endpoint that drifts between arms (model reload, different quantisation) is caught only by A9's 20×5 determinism probe, run once at the start.
12. **We cannot prove the flat arm's context is what a commercial provider's flat context would have been**, because AMB never persists `raw_response` (`runner.py` sets it to None on save). Our regime-correspondence claim in G13 rests on reading their code, not on comparing artifacts.
